This is to report addon visualization of output of T2.3 CRC biomarker identification and clinical knowledge base.

 

1.    The clinical knowledge base consists of around 100 articles and reports categorized into these sections:

a.    Cancer experts' opinion and publications

b.    Clinical study

c.     Existing open dataset from the EU

d.    Genome cancer prevalence

e.    Microbiota

f.      ONCO-CRISPR

g.    ONCO-CTC

h.    ONCO-NMR

i.      ONCO-VOC

j.      Pan-cancer analysis of whole genome

k.     proteins

l.      Whole genome analysis for large cancer population and corresponding cancer stratification

The recent advances in machine learning algorithms and large language models have enabled the ability to programmatically extract information from human readable formats into structured, context aware forms. In the context of deliverable T2.3 a proof of concept was created and tested in order to:

1.    Construct a knowledge graph consisting of triplets of knowledge (subject, object, predicate) from source documents.

2.    Recognize biological, statistical and other entities that are to be represented in the knowledge graph.

3.    Extract specific information related to performance of biomarker-based tests to predict risk of CRC or quantify risk factors.

4.    Visualise the knowledge graph and recognized entities in a highly customizable form as a web application.

 

Visualization in knowledge graph

The selected articles and reports (result of previous efforts towards the objectives of T2.3) were used to create an initial knowledge graph that visually represents findings as triplets (subject, object, predicate), where subjects and objects are represented by nodes and predicate is represented by an oriented edge. The visualization has been made publicly available as a static web application via GITHUB pages at the following URL: https://digital-biosystems.github.io/oncoscreen-kb/

 

The complete graph structure is depicted in Figure 1.

Subjects and objects are visualized as nodes, predicates are visualized as edge which connect the respective nodes. The node colour represents the identified entity type.

The knowledge base and the visualisation contain four separate knowledge graphs. The full graph is based on all 100 articles making up the T2.3 knowledge base. The consensus knowledge base consists of 8 articles that were identified by ChatGPT's Consensus addon as most relevant to biomarkers of colorectal cancer specifically. This graph was produced as a proof of concept for manual selection of relevant articles supported by LLMs (an expected future use case). The two remaining visualisations are similar to the full graph based on all 100 articles but processed by different LLM models to extract knowledge from the articles. These graphs were added to allow the user to assess the impact of the choice of underlying LLM on the final knowledge graph. Methods

The process cycle is presented in Figure 7. All articles and reports were downloaded to a shared directory and subdirectories corresponding to the categories listed in section 1.a.-l. Every article is presented as a PDF file.

 

Figure 7. The process cycle to extract knowledge from articles, construct triplets and knowledge graph(s). Extracting textual content from PDFs is done by the open-source GROBID service [2]. Information extraction from the full text is performed by selected large language model via ollama tool [3]. Triplet and performance statistics identification are performed by selected large language models and also by entity recognition models.

The GROBID service [2] is a machine learning library for extracting, parsing and re-structuring raw documents such as PDF into structured XML/TEI encoded documents with a particular focus on technical and scientific publications. It is used to format title, authors, journal name, year, doi, abstract and full-text content information in a structured XML.

The full text of every article is then processed by a local deployment of selected large language models (LLM) using the open-source ollama tool. The LLM extracts key findings. Triplets and performance statistics are constructed using a second call to the LLM and entity recognition is performed by ER model en_ner_bionlp13cg_md.

 

Among others the following open-source models were tested for the information extraction step:

         Llama3.3:70B q8 70 billion parameter model llama3.3 with quantization 8 bits

         qwen3:32b 32 billion parameter model qwen3 with quantization 4 bits

         deepseek-r1:32b-qwen-distill-fp16 32 billion parameter model deepseek-r1 distilled by qwen model architecture

         deepseek-r1:70b-llama-distill-q8_0 70 billion parameter model deepseek-r1 distilled by llama3.3 model architecturre

         mistral-large:123b 123 billion parameter model mistral-large with quantization 4 bits

         llama4:17b-scout-16e-instruct-q4_K_M

Frontend

Frontend development was performed using web components standard and utilizing the Aurelia 2 framework that facilitates development of independent components.

The Sigma.js [4] open-source JavaScript library is used to render interactive network (graph) visualizations in the browser. In order to allow users to explore and manipulate complex node-and-edge data with smooth panning, zooming, and styling.

The Graphology [5] library is integrated to structure the graph presented by Sigma.js into a 2D canvas. The ForceAtlas2 algorithm and NoOverLap algorithm are executed upon loading the graph to place related nodes and edges close together.

 

Limitations

Representing the T2.3 clinical knowledge base as a knowledge graph, was a late addition to the ONCOSCREEN project and therefore there are limitations to the current implementation. The exact nature of nodes and edges can be represented in different ways. To take the example of Figure 2, in this instance a cluster of genes was represented as a single node. One could also represent this same knowledge as separate nodes for each gene with individual edges connecting to a centralized node for dMMR. Which representation is optimal, depends on the downstream use cases for the knowledge graph. Further work could be performed to optimise the extraction of knowledge from the articles, enable knowledge extraction from figures and tables, including additional links to external databases containing information on medical entities, risk factors, genes etc. These types of improvements are unfortunately beyond the scope and budget of T2.3.
